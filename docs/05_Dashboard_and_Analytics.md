# Dashboard

## 1. Назначение документа

Данный документ описывает архитектуру **Dashboard** проекта **Study Recommendation System**, его структуру, источники данных и принципы организации визуализации.

Dashboard является завершающим компонентом системы и предназначен для представления результатов анализа обучения, рассчитанных на предыдущих этапах обработки данных.

## 2. Назначение Dashboard

Dashboard является пользовательским интерфейсом системы и объединяет результаты работы всех предыдущих компонентов проекта.

Его основная задача — представить накопленные данные в удобной для анализа форме и помочь быстро ответить на вопросы:

- какие темы уже хорошо освоены;
- какие разделы требуют повторения;
- почему система рекомендует повторить определённые темы;
- какие задачи предлагаются для дальнейшего обучения.

Помимо визуализации результатов Dashboard предоставляет средства навигации, фильтрации и поиска, позволяя работать с данными без обращения к таблицам базы данных или SQL-запросам.

---

## 3. Архитектура Dashboard

Dashboard является слоем представления (**Presentation Layer**) и не содержит собственной бизнес-логики.

Все алгоритмы анализа обучения и формирования рекомендаций реализованы в PostgreSQL.

Dashboard использует аналитические представления в качестве основного источника данных, а SQL-запросы Metabase применяются только для подготовки отдельных визуализаций, агрегирования показателей и работы пользовательских фильтров.

```text
PostgreSQL
      │
      ▼
Analytics Views
      │
      ▼
Recommendation Views
      │
      ▼
SQL Queries (Metabase)
      │
      ▼
Dashboard Visualizations
```

Такое разделение позволяет независимо развивать алгоритмы анализа и пользовательский интерфейс.

Изменение структуры Dashboard не требует изменения логики Recommendation Engine, а развитие аналитических представлений автоматически становится доступным для визуализации.

## 4. Структура Dashboard

Dashboard состоит из трёх самостоятельных страниц, каждая из которых решает собственную задачу.

### Обзор обучения

Первая страница предназначена для анализа общего прогресса обучения.

Она отображает:

- статистику базы знаний;
- уровень освоения по предметным областям;
- прогресс по тематическим группам;
- прогресс по подгруппам.

Основная цель страницы — дать общее представление о текущем состоянии обучения и определить области, требующие внимания.

### План повторения

Вторая страница отображает результаты работы Recommendation Engine.

Она включает:

- приоритет повторения тем;
- причины формирования рекомендаций;
- рекомендуемый уровень сложности;
- список рекомендуемых задач;
- сводную статистику по рекомендациям.

Эта страница представляет собой персональный план повторения, сформированный на основании истории обучения.

### Task Bank

Третья страница предоставляет доступ к каталогу задач.

Она позволяет:

- просматривать задачи банка;
- использовать фильтрацию по разделам и подгруппам;
- анализировать покрытие банка задач;
- просматривать характеристики задач (паттерн, уровень сложности, предметная область).

Task Bank может использоваться как совместно с Recommendation Engine, так и независимо от него.

## 5. Почему Dashboard разделён на три страницы

При проектировании рассматривался вариант размещения всех графиков и таблиц на одной странице.

Однако по мере развития проекта количество визуализаций значительно увеличилось, что усложняло навигацию и снижало удобство работы.

Поэтому Dashboard был разделён на три самостоятельные страницы, соответствующие основным сценариям использования системы:

1. анализ текущего прогресса обучения;
2. работа с рекомендациями;
3. просмотр полного банка задач.

Такое разделение делает интерфейс более понятным и позволяет развивать каждую страницу независимо от остальных.

## 6. Источники данных

Основным источником данных для Dashboard являются аналитические представления PostgreSQL.

| Представление | Используется |
|--------------|--------------|
| `vw_learning_progress` | Обзор обучения |
| `vw_learning_features` | Аналитические показатели |
| `vw_recommendation` | План повторения |
| `vw_recommended_tasks` | Рекомендуемые задачи |

Для построения отдельных карточек, графиков и фильтров используются SQL-запросы Metabase, работающие поверх этих представлений.

Такой подход позволяет избежать дублирования вычислений и повторно использовать одни и те же данные в различных элементах Dashboard.

## 7. Направления развития

В дальнейшем планируется развитие Dashboard по нескольким направлениям:

- визуализация изменения Mastery Level во времени;
- анализ динамики повторений;
- отображение истории обучения по отдельным паттернам;
- прогнозирование изменения уровня знаний;
- расширение возможностей фильтрации;
- интеграция с Telegram-ботом и веб-интерфейсом.

Архитектура Dashboard позволяет добавлять новые страницы и визуализации без изменения структуры базы данных или алгоритмов Recommendation Engine.
